## Evidence: one high-impact bug in an implemented flow

**RED before fix:** Test-only [commit `597f423a`](https://github.com/khaledtag93/dynamic-ecommerce/commit/597f423ad75ff0b40b8b6ce5be40a4b2ec154865), CI [#38995215153](https://github.com/khaledtag93/dynamic-ecommerce/actions/runs/38995215153), `completed/failure`: one new `AccountRememberTokenRotationTest` failed *exactly* on `assertNotSame($rememberTokenBefore, $user->fresh()->getRememberToken())` after successful real form POST changing password, while **993 existing PHPUnit tests passed / 19,230 assertions**. Browser-like test explicitly carries initial session cookie through POST login with `remember=1`, asserts remember recaller cookie was issued, carries resulting authenticated session cookie through PATCH password update, asserts user still signed in and new password hash valid. Thus unlike a session-less unit test, a concrete session/cookie journey was exercised.

**Minimal fix:** `AccountController::updatePassword` persists both the newly hashed password and a freshly generated 60-char remember token in **one** `save()`, via Eloquent's `setRememberToken(Str::random(60))`. Existing `current_password` validation, form, response JSON/redirect and current-session login preserved. A negative regression asserts wrong current password does **not** alter hash/token. No explicit all-sessions revocation, schema, provider, config/permissions or policy changes.

**Final CI:** Verify final commit's matching GitHub Actions `completed/success` and actual test summary independently before marking SOURCE FIXED; otherwise still OPEN. Do **not** claim old recaller replay against live QAS was tested or every other existing session was invalidated.
