## Safe response contract
- Mail resolved from the **actual Laravel config repository** (`mail.default` + selected `mail.mailers.*.transport`) and reduced to a strict allowlisted transport and boundary. `array` only proves **Laravel's selected mail transport is local/non-delivering**, never universal outbound isolation; `log`, composite/failover and unknown options do not get an isolation PASS.
- WhatsApp uses approved Boolean DB overrides when present, otherwise **resolved Laravel config fallbacks**. Master, event toggles, queue toggles and Notification Center channel flags stay distinct. A disabled queue can mean synchronous delivery; `queue_off_can_dispatch_sync=true` is an explicit caveat. Any provider/global isolation remains `UNVERIFIED`, even if a manager-level master switch reads OFF.
- Active automation rules return **only a count**.
- Email `failed` `notification_dispatch_logs` return **only aggregate counts** in `TEMPLATE_RENDER`, `TIMEOUT`, `RATE_LIMIT`, `RECIPIENT_VALIDATION`, `OTHER_OR_UNKNOWN`. Classification is performed by a fixed SQL CASE inside the connected database; the response does not SELECT or return per-row raw error strings, payloads, recipients, IDs or exceptions. This is a category hint, not a proven external provider root cause.
- Missing, mismatched, unsupported, or broken environment/database/schema fails closed with a non-diagnostic error; no fallback to QAS source-only defaults or a false safe result. Unknown flag values return `UNKNOWN`.
- The service performs SELECT-only queries and does **not** call any writer. Normal Laravel authentication/session middleware may maintain session state independently of this service; therefore do not interpret a GET request as a promise of *zero filesystem/session activity* in the entire application stack.
